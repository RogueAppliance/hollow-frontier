# Hollow Frontier — Decisions

Calls made in place of asking, and the reasons behind them. PLAN.md keeps the standing ones; this is the full log, condensed on 2026-11-01 to what still holds (superseded calls folded into what shipped; the long form is in git history, and the original phase specs are in PHASE_SPECS.md). Add new decisions under their phase, or under "Since phase 31" for work that isn't one. Record the call and why, not what the code already shows.

## Engine and tool notes

- **26.x datagen split:** recipes, loot tables, advancements and worldgen are datapack registries gathered through `GatherDataRegistryEntriesEvent` (`event.recipe(...)`, `.lootTable(...)`, `.add(Registries.X, ...)`). Models, lang and tags go through `GatherDataEvent.Client`. `runData` uses `clientData()`, so it covers both. The registry-entries event takes one bootstrap per registry, so merge contributors (e.g. ore + spawn biome modifiers) in one lambda, and pass all loot sub-providers in one `lootTable(...)` call.
- **26.3 API notes:**
  - `Holder.getKey()` is deprecated for removal: use `key()`. Configured features are `Registries.FEATURE` holding `Feature` instances (`new OreFeature(List<BlockReplacement>, size)`). `RecipeBuilder.save(output, id)` throws when `id` equals the default (`ModRecipeProvider.save()` handles it); vanilla's `nineBlockStorageRecipes` writes `minecraft:` ids, so use our `storage()` helper.
  - Input is SDL, not GLFW (no `org.lwjgl.glfw`). Key mappings use `InputConstants.Type.KEYBOARD` + `InputConstants.KEY_*`; categories are `new KeyMapping.Category(id)` registered through `RegisterKeyMappingsEvent.registerCategory`, lang key `key.category.<ns>.<path>`.
  - `Entity.hurtMarked` is gone: `push()` sets `needsSync`, and a pushed player needs a `ClientboundSetEntityMotionPacket`. An entity's `move` throws if run on the client. Armor uses `Item.Properties.humanoidArmor(ArmorMaterial, ArmorType)` plus an `EquipmentAssetProvider` (layers humanoid, humanoid_leggings, humanoid_baby). Entity types without loot (projectiles) need `EntityType.Builder.noLootTable()`.
  - `Player.displayClientMessage` → `sendSystemMessage` / `sendOverlayMessage`; `Player.drop(stack, thrown, Prediction)`.
  - In BuiltInRegistries, `ENTITY_TYPE` registers before `ITEM` (spawn eggs can call `.get()`) and `DATA_COMPONENT_TYPE` after (don't set mod components in item constructors). During datagen items have no components bound, so no `ItemStack` can be made there: written books and sign text are encoded by hand through the vanilla codecs (`WrittenBookContent.CODEC`, `SignText.CODEC`).
  - `Blocks.RED_WOOL` etc. are `Blocks.WOOL.red()` (`ColorCollection`); `Blocks.COPPER_BLOCK` is a `WeatheringCopperCollection` (`.weathering().unaffected()`). Block `codec()`/`simpleCodec` are gone. Loot entry builders are `UniformContainerBase.Builder`. Custom block models in datagen use NeoForge's `ExtendedModelTemplateBuilder`, registered with `BlockModelGenerators.createSimpleBlock(block, plainVariant(model))`. Structure NBT is written with `NbtIo.writeCompressed` plus `NbtUtils.addCurrentDataVersion`.
  - Transfer API: `ResourceHandler<FluidResource>` with `Transaction.openRoot()`; `FluidStacksResourceHandler` is the base tank; `Capabilities.Fluid.BLOCK` registered via `RegisterCapabilitiesEvent`. A fluid's sprites come from a client fluid model (`RegisterFluidModelsEvent`), or Jade and JEI draw it as the missing texture.
  - Screens override `extractBackground(GuiGraphicsExtractor, ...)`. `getCraftingRemainder()` returns an `ItemStackTemplate`. Recipes extend `SingleItemRecipe` and need a registered `RecipeBookCategory`.
  - Deprecated tags: use `Tags.BlockItems.CHESTS_WOODEN.item()` and `Tags.BlockItems.GLASS_PANES.item()`. `#minecraft:dirt` no longer holds grass, mud or moss: "ground plants grow on" is `#minecraft:substrate_overworld`. `TemptGoal` needs the `tempt_range` attribute.
- **GeckoLib 5:** assets go in `assets/<ns>/geckolib/models/entity/<name>.geo.json` and `geckolib/animations/entity/<name>.animation.json`, textures in `textures/entity/<name>.png`. Use `DefaultedEntityGeoModel(id).withAltTexture(id)`. `ItemInHandGeoLayer` needs the renderer's `R` bound to `LivingEntityRenderState & GeoRenderState`. Drive animations from synced entity data or item components, never trigger packets from server logic, so mobs and other players see them. `hardcodedHeadRotation` replaces a bone's rotation, so look rotation goes on a `neck` bone and is added to the animation. Rotation sign: a positive X tips a bone's +Y end forward (-Z). API source: `geckolib-neoforge-26.3-5.5.7-sources.jar` on the GeckoLib Cloudsmith maven.
- **Glowing GeckoLib mobs:** GeckoLib 5.5.7 never draws the entity outline, so `GlowingGeoRenderer` (the base of all our GeckoLib entity renderers) submits the posed model again with vanilla's `outline` render type when the entity glows. Always white (team colours would need GeckoLib to pass a vertex colour). Drop it if a GeckoLib update renders outlines itself.
- **Testing:** game tests live in `com.hollowfrontier.gametest` (main source set; inert unless NeoForge enables game tests), on `test_platform`, `test_garden` (16) and `test_yard` (48) structures from the blueprint datagen. Fake players don't fire tick events, so tick-driven logic exposes a public per-player method (e.g. `CowboySetBonus.update`). A test player is only hurt once the server counts its client loaded (wait ~80 ticks). The game test server loads no datapack dimensions, so Hollow Earth tests build the generator from the registries, and crossing tests stand the Nether in for it. `HurtByTargetGoal` ignores a hurt stamped tick 0. Tests that make fake players remove them when they finish (`TestPlayers.leave`), and mobs a test relies on are pinned so they can't despawn. Known timing-sensitive tests: `salamander_basks_on_vent`, `raven_perches_on_stone`, `posse_rides_out` (each fails now and then and passes on a rerun).
- **Art pipeline:** flat placeholders (`genPlaceholders`) → procedural pixel art (`tools/textures/TextureArt.java`). Reworked vanilla textures are made by TextureArt straight from the patched game jar in `build/moddev/artifacts` (without it, the hand-drawn fallbacks stay). Models with many cubes are built by code (`tools/models/*Models.java`: guns, airship, barmaid, saucer...), since hand-written per-face UVs are error-prone; animation JSON stays hand-written. `runPhoto` (PhotoBooth) is the visual check; it releases every forceload when it starts and quits (left over, they made every start load thousands of chunks).
- **Datagen** covers recipes, loot tables, block/item models, blockstates, tags, lang (en_us), advancements, worldgen and structure NBT. Nothing generated is hand-edited. Run `runData` before `genPlaceholders`, as separate commands: `genPlaceholders` reads the models, and run first it makes placeholders for whatever the old models named.

## By phase

### Phase 2: materials
- **Brass** = 3 copper ingots + 1 gold nugget → 4. Zinc was cut in 9c: the early game uses vanilla metals, copper is plentiful and barely used by vanilla, and brass stays as the steam tech's look.
- Plates are 4 ingots → 2 (no hammer tool); gears 4 ingots + 1 iron nugget → 2.
- **Other mods' brass:** every brass input takes the `c:` tags. The crafting-table alloy has a `hollowfrontier:brass_alloying` load condition: with `alloying = AUTO` (startup config, the default) it switches off when another namespace's item is in `c:ingots/brass` (e.g. Create's), so we don't undercut that mod. ALWAYS/NEVER override. Startup config because this NeoForge has no COMMON type and the condition runs before any world config loads.

### Phase 3: guns (black powder)
- **Percussion muzzleloaders, period-accurate:** Cap & Ball Revolver (1851 Navy), Plains Rifle (Hawken), Double-Barrel Muzzleloader. Hitscan with a tracer; ammo and reload state in item components.
- **Loading:** one chamber per `loadTicks`, timed by a `reload_start` game-time component, ticking only while held. Every load costs a paper cartridge and a percussion cap; firing or the reload key cancels.
- **Wet powder:** rain gives a 20% misfire chance, underwater always misfires; a misfire spends the round. Ammo shows in the tooltip, so the item bar keeps showing durability. Mob gun damage scales with difficulty; mob guns are weaker (`GunTypes.OUTLAW_*`).
- **Display:** first and third person use no rotation; the GUI uses Euler `[90, tilt-90, 90]` because NeoForge datagen writes `right_rotation` beside a `left_rotation` the 26.3 loader ignores. Players hold every gun in the crossbow pose (a one-handed revolver pose would need a custom `ArmPose`).
- **Outlaw aiming:** outlaws only shoot standing still with the gun raised for 10 ticks, closing to about 70% of range. A synced `GunPose` (lowered, aiming, reloading) drives an arm controller over the walk swing; while aiming the body snaps to the head, or vanilla's body lag leaves the arms off-target.
- **Headshots** (2026-10-31): a player's shot at head height (height only, so generous on four-legged beasts, on purpose) does more: the rifles double, the rest half again. Mobs never get the bonus. The shooter alone hears a "ding".

### Phase 4: cowboy gear
- **Cowboy armor:** defense 2/4/3/2, durability multiplier 10, leather repair. Set bonus +20% mount speed, a transient modifier refreshed every 10 ticks.
- **Lasso:** consumed on a catch, so it can't duplicate vanilla leads; leashes only within `leashSnapDistance`, otherwise just pulls.
- **Horse gear:** any tamed `AbstractHorse`, stored as attachments (`horseshoe_tier`, `saddlebags`); horseshoe stats are permanent attribute modifiers. Saddlebags use the vanilla 9x2 chest menu. Main-hand only.
- **Dynamite:** thrown and fused (2.5 s, power 2.5, breaks blocks like TNT), bounces off blocks, stops against mobs, credited to the thrower.

### Phase 5: outlaws, bounties and townsfolk
- **Gangs** spawn lazily, the first time a poster carrier comes within 64 blocks of the hideout (chunks are loaded then); `BountyData.spawned` stops a second spawn. Overworld only.
- **Rewards:** the poster is used up when the badge is turned in; badges pay even without the poster.
- **Coins:** copper and gold, minted from 4 vanilla nuggets (2x2), 9 copper = 1 gold both ways.
- **Townsfolk** are `AbstractVillager`s with fixed coin trades in code (not 26.x data-driven `TradeSets`). All humanoids share one GeckoLib model (`humanoid`) with per-entity textures. Trades sound like coins or a pour, not a villager.
- **Barmaids:** a `Townsfolk` with no wander goal, on her own feminine model. Five hostesses (`Hostess`: Miss Ruby, Clementine, Josie, Miss Belle, Lupe), each with a look, greetings and two cheaper house specialties. Her name is a translatable custom name, kept if a player renames her. Flirty but PG.
- **Drinks** are trade and chest loot only. **Tipsy** (I-IV) stacks per liquor; each level adds gun spread, III brings nausea, past IV a blackout. Coffee takes a level off, sarsaparilla clears it. Effects are applied in code (`DrinkItem.finishUsingItem`) because Tipsy stacking can't be data-driven.
- **Lawmen** (Sheriff, Deputy, U.S. Marshal, Ranger) are `PathfinderMob`s, not monsters, and never despawn.

### Phase 6: frontier structures
- **Blueprints in code** written to NBT by datagen, with no rotation in the blueprint itself (pieces face north; the jigsaw turns them). Template entities are finalized on placement, so camp outlaws get their guns. Structure `spawn_overrides`: no monsters in towns and saloons; outlaws only in camps.
- **Connected blocks** (fences, bars, panes, walls) keep their connections in the block state and placement copies states as saved, so `Blueprint.toNbt` settles them first.
- **The town is a jigsaw** (see phases 23-24 for what it became).

### Phase 7: steam
- **Transfer:** every holder pushes steam each tick to lower-pressure neighbours (`SteamNetwork.push`). No network graph: simple and stateless; long lines settle over a few ticks.
- **Conversion:** 1 mB water → 1 mB steam, 10 mB a tick while burning; a coal makes 16 B (about 40 crushes or 640 drill blocks).
- **Machines** extend `BaseContainerBlockEntity`, so fuel resolves through `COOKING_FUEL` and hoppers work.
- **Steam Drill:** a pickaxe+shovel `Tool` rule set; the no-steam slowdown is per player (`PlayerEvent.BreakSpeed`), since `Item` is a shared singleton. Steam comes from canisters.
- **Steam Handcar** rides rails; depot standpipes refuel it.

### Phase 8: airship and polar gateway
- **Airship:** a `VehicleEntity` moved on the server only, clients interpolating (as the handcar). The pilot flies with their own keys via `getLastClientInput`: jump climbs, sprint descends (sneak is vanilla's dismount). A second passenger sits aft. The hit box is the gondola; the envelope is only drawn (the renderer widens its culling box). Third person pulls back to 12 blocks aboard (`CalculateDetachedCameraDistanceEvent`).
- **Fuel:** coal or charcoal by hand, boiled into a 16 B tank; no water needed (a closed condenser loop). With no steam it sinks gently and never falls; parked it burns nothing. It also fills from canisters or a steam holder under its keel (a mooring mast). Only its owner can break it, and its fuel is kept when broken (31a).
- **Polar Gateway:** a ring of 12 unbreakable frame stones in an ice crater in snowy biomes (`c:is_snowy` since phase 30). Gateways are found, not built (the frame item is creative-only). The **Polar Resonator** spends 2,000 mB of steam to wake one: this is what gates the Hollow Earth behind steam tech.
- **Polar Compass:** stores the nearest gateway as a lodestone tracker with no lodestone, so the vanilla compass model points it. In the Hollow Earth it points to the nearest return gateway.
- **Crossing:** a vanilla `Portal` block. The Hollow Earth is 1:1 with the Overworld; the first crossing builds a return gateway at the same x/z and records the pair in `GatewayLinks`, so later trips land at the same spot.
- **Made a show of:** the ring lights stone by stone, then the well floods and a beam rises (vanilla beacon code, shader-safe). No nether swirl or portal sound: a frost overlay and rising hum instead. On the way in, players fall down **Symmes' shaft** (bored through the crust on the first crossing, bedrock-capped so it's dark), hang for the reveal swell and a first-visit title card, then drift down onto the ring. The server keeps them safe (hidden Slow Falling, fall distance reset, fall damage cancelled during the descent).
- **Left as is:** vanilla's "experimental settings" warning shows once per world (any extra dimension triggers it; hiding it needs a mixin into world loading). "Loading terrain" shows briefly between worlds.

### Phase 9a: the Hollow Earth's world
- **Layout:** y -64..319. Land mostly 64-110, Highlands to ~180, sea level 63. The crust's underside sways round y 236 with hanging spires and rare floating islands near y 200; crust to 314, then shell bedrock. About 150 blocks of open air. Caves come from vanilla carvers, so the crust and islands stay solid.
- **Crust rock lets sky light through** (so does shell bedrock). Sky light comes from the top of the world, so a ceiling of ordinary stone would leave the land dark (monsters everywhere, no crops); a Nether-style dimension was rejected for that reason. Mined crust rock is a building stone.
- **Terrain follows the climate**, as vanilla's does: one set of noises picks the biome and shapes the land (Highlands where high or cold, Badlands hot and dry with mesa terraces, Steppes dry and temperate, Jungle the rest), thresholds shared in `HollowBiomes`. Regions are ~600-1000 blocks.
- **Biomes** are built from scratch (no vanilla builder, so no vanilla sky colour). The dimension owns the green-gold sky; biomes tint only the fog. No rain. Haze from 48 to 480 blocks.
- **The inner sun** is drawn *in* the world, not the sky box (the crust would hide a sky-box sun): emissive quads on vanilla's `eyes` render type (shader packs treat it like glowing mob parts), hung under the crust over the camera and scaled to look the same size. Time is fixed; beds set spawn but can't be slept in.
- **Placement under a ceiling:** heightmaps find the crust, so vanilla features are re-placed with `hollowfrontier:open_air_scan` (down through air to the first solid block). Everything later that places on the ground must do the same. Falls of water and lava come from springs in the crust's underside; `FAST_LAVA` is dimension-wide so lavafalls reach the ground.
- **Spawning:** the dimension has `hasCeiling` true so `NaturalSpawner` looks down past the roof (it doesn't affect sky light).
- **Landing** (`HollowLanding`): the highest level, open-air floor below y 188 with a roof above; never the crust top, an island or a cave. The return gateway clears trees above it.
- **Hooks:** biome tags `has_mammoths`, `has_terror_birds`, `has_megatherium`, `has_glyptodons`, `has_gray_labs`, so other biomes can join by tag.

### Phase 9b: flora, creatures and lore sites
- **Split** into 9b1-9b3 (one session each).
- **Flora:** five unconfigured features (tree fern, cycad, crystal outcrop, ash vent, standing stonework), grown before the jungle trees so they take their ground first. The jungle was thinned to 18 trees a chunk (at 30 the understory was black). Glowworm vines on the crust were cut: 150 blocks up in daylight, nobody could see them. Vanilla blocks where they do the job (amethyst outcrops; calcite, diorite and quartz stonework).
- **Ambience:** per-biome vanilla-remix sounds and particles; the "cinder moths" idea became particles, not mobs.
- **Small creatures** (`PathfinderMob` + GeckoLib): the Fern Skitter (steals dropped food; tameable with meat since 2026-10-31), Glassback Hare (glowing back crystals), Ash Salamander (walks on lava like a strider, which needs the strider's liquid collision shape too, and basks on vents) and Pale Raven (perches on stonework; flushed, it flies toward the nearest Kindled site, a breadcrumb). Vanilla drops only.
- **Lore sites:** our own structure type, `HollowSiteStructure`: reads the bare noise column at the piece's middle and corners, refuses water, lava, islands and slopes over `max_slope`, sets the floor at the average and beards the land to it. It tries five spots round its chunk, since big footprints rarely find level ground. Blueprints build their floor at layer 0 (or the beard leaves foundations bare). Sites are landmarks 25-37 blocks across, with exclusion zones so camps, labs and Kindled sites don't land on each other, and trees and big flora skip any chunk a site references.
- **The sites:** Kindled henge, gate or temple (Highlands); the abandoned Gray lab; the Symmes expedition camp round its crashed airship, with the journal (1889, "E. Hartwell", a made-up name).
- **Gray Probe:** hovers watching the nearest player; bolts when approached, stared at (the Enderman test) or hit, then blinks out.

### Phase 9c: ores and gear
- **Starsteel** (the lore keeps orichalcum as the Concavians' own word, after Plato): a tier between diamond and netherite. Tools mine as diamond, 1800 uses, speed 10 (the fastest), enchantability 22; armor has diamond's defense and toughness 2.5 but no knockback resistance (netherite keeps that). One **Starsteel Paxel** instead of four tools (it strips through NeoForge's multitool `transformBlock(context, holder)`, since vanilla refuses a transformer that isn't the stack's own). Art: crimson with pale-gold edges and an ice-blue phlogiston stone, so it doesn't read as copper or gold.
- **Sun-forged:** worn or held starsteel mends 1 point every 5 s in full sky light by day (always under the inner sun). Slow, so it doesn't replace Mending, but a reason to wear it under the open sky.
- **Starsteel Horseshoes:** +30% speed, +0.15 jump, no fall damage for horse and rider (horses skip the fall event, so incoming fall damage is cancelled instead).
- **Phlogiston** burns as long as a coal block, lights the Phlogiston Lamp, and its ore glows. Ores are underground, so plain height ranges; both need an iron pickaxe.
- **Overworld seeds:** Gazette rumours, and a rare strange grave on Boot Hill ("The airship's pilot. Not of this world. April 1897", after the Aurora story) with a chest.
- **Reworked vanilla art** was allowed here (recoloured and tweaked, not copies, each marked in ASSETS.md): the metals, ores and armor are reworked iron, emerald, gold and redstone.

### Phase 10a: wild megafauna
- **The four** (GeckoLib, `Megafauna` holds what they share): the Woolly Mammoth (neutral; the herd closes ranks when one is hit, and stragglers walk back to the herd), Terror Bird (hostile by day, since the Hollow has no night; hunts small creatures too and keeps clear of mammoths, so a herd is a refuge), Megatherium (neutral; browses tree leaves, only with mobGriefing) and Glyptodon (passive; hunkers when threatened, sheds scutes like an armadillo).
- **Terror birds stay scarce:** as monsters they'd come and go in numbers, so `checkSpawnRules` passes 1 natural spawn in 4 and never with 2 already within 96 blocks. It runs with its own move controller (vanilla sprinting would add 30%).
- **Spawns** go through biome modifiers on 9a's tags; big mobs also need headroom.
- **Drops and uses:** the Oliphant (calms mammoths and megatheria, scares terror birds), Mammoth Steak, Talon Knife (a kill made with it gives one more hide, tusk, talon or scute: `#hollowfrontier:skinnings`; a built-in Looting I was the first idea, but items can't carry data-driven enchantments at registration), Hide Barding, and Glyptodon shell armor (the full set shells you up while sneaking: projectiles a quarter, explosions half).

### Phase 10b: Gray experiments
- **Tagged specimens** are a synced `GrayTagged` flag on the megafauna, not four more entity types: permanent modifiers (health x1.5, armor +6, speed and attack up), and the implant overrides their nature (tagged mammoths hunt players, the tagged glyptodon never hunkers, none heed the Oliphant). They drop Gray Tech Fragments.
- **Where they come from:** the live station's pens and loose specimens tethered to it; separately, 3% of wild megafauna spawns are escapees, a hint that a station is near. Checking for a nearby station at spawn was ruled out: chunk-generation spawns can't safely read neighbouring chunks' structure references.
- **Live Gray field station:** shares the `gray_lab` structure set with the abandoned lab so the two never overlap. No beacon beam to mark it: beacons don't light under the crust.
- **Gray Sentinel:** a probe that never flees; it beams a visible player for 2 s (breaking sight stops it), stuns them and sets every tagged specimen within 48 on them.
- **Signal Locator:** takes a bearing on the nearest live station, like the Polar Compass.

### Phase 11a: sightings and signs
- **How often:** Overworld nights, a 6% roll every minute, at most one mystery a night (about one night in two). A night slept through rolls 30% for a mutilation or circle found by morning, since nothing ticks while the night is skipped. All switchable since phase 30.
- **Airship sightings** are cosmetic cigars of lights after the 1896-97 wave, crossing well inside simulation distance so they never freeze in unticked chunks.
- **Mutilations** leave a `CattleCarcass` (vanilla's cow, reworked) with faintly glowing cuts and a ring of coarse dirt; **crop circles** lay ripe wheat flat as Flattened Wheat. Fields are found by looking down each column for the topmost ripe wheat (the surface heightmap fails under a roof).
- **The stake-out:** an awake player 20-64 blocks off sees a Gray Probe do the job, and can spook it or kill it mid-job.
- **Reported:** `MysteryLog` feeds the Gazette and the townsfolk's grumbles.
- **The Boot Hill grave's payoff:** the Strange Skull and the pilot's Logbook (in vanilla's `minecraft:alt` glyph font, so it can't be read; the English underneath is a clue).

### Phase 11b: men in black dusters
- **Implanted collaborators,** the outlaws' finished product: drifters the Grays took and sent back as handlers, most of them willingly. That ties them to the outlaws and gives the Mothership's fall something to break.
- **Suspicion** (a player attachment, 0-100, kept through death: "they don't forget a face") rises for killing the Grays' things, using their gear and being seen carrying it; it falls by selling those things to the men in black and slowly over time. 25 warned, 60 marked (shot on sight, hunted). Creative players draw none.
- **They arrive after mysteries** (a visit booked half a day on), lean on the Gazette editor (a "correction" runs instead of the report for 3 days), buy strange goods, and hunt marked players at night.

### Phase 12a: the Kindled
- **The Kindled** are the surviving Concavians, luminous and benevolent: traders in phlogiston shards and the player's allies. Their story is told a line at a talk, nine lines in three tiers of standing, ending at the truth about the Grays, the outlaws' implants and the men in black.
- **Standing** (a player attachment, kept through death): Friend at 4, Ally at 12 (the Kindled Sigil, given once). Hurting a Kindled costs standing and rouses the guardians; below 0 they won't trade and the guardians shoot on sight. Ally-only offers are taken off the merchant's list while anyone else trades, since offers belong to the merchant, not the player.
- **Crystal Guardians** hold their posts and target the Grays' things, those who've wronged the Kindled, and strangers carrying Gray goods. A guardian's first shot at a stranger whose only fault is what they carry is a harmless warning (three guardians had put a survival player at 3 hearts in two seconds).
- **Kindled Sigil:** held, it makes outlaws and men in black within 32 glow: the implant shows.
- **Crystal Ruins** in the Highlands, never near a Kindled site; ravens fly there too. The crystal is a building stone that drops itself.

### Phase 12b: the Sun Archon
- **Who it is:** the last king of Concavia, who went into the inner sun to hold it against the Grays and came out corrupted. Its Sun Temple stands in the Ember Badlands, set close (24/8 chunks) because few badlands spots are level enough; allied Kindled point the way.
- **Three phases:** the King (staff and solar beam), Corona (shielded above the arena while any Sun Pylon stands: break the pylons) and Eclipse (faster, fire, a sunburst). With no survival player near for 10 s it resets to its throne, healed, pylons restored: losing costs nothing you can't come back for.
- **Drops:** one Phlogiston Core and one Starsteel Crown (pools without looting, so never two), sunstone shards; +6 Kindled standing to everyone near.
- **Phlogiston beam damage** (`hollowfrontier:phlogiston_beam`) is shared by every beam in the mod; the Crown halves it.
- **The Concavian Codex** is a written book that rewrites itself when opened: the mod's advancement guide, chapter by chapter.

### Phase 13a: the Grays arrive
- **The Grays fly saucers,** the Concavian craft they stole. The 11a cigar "airships" stay as what frontier folk took their lights for. Wrecks are saucers too.
- **Flyovers and abductions:** Overworld nights, a 5% roll a minute. 40% stop to beam an animal or an upright player; sneaking or stepping out breaks the hold. Players get Levitation (their movement is their client's). A taken player gets **missing time**: set down 300-700 blocks away, dazed, +10 suspicion. `abductPlayers` turns that off.
- **Gray Wardens** keep their distance and fire rays, and blink away when hurt. Two guard each crash site; a few roam the Gray-lab biomes.
- **Crash sites** in the Overworld (by heightmap, clear of towns) and the Hollow Earth (as a hollow site), with Saucer Wreckage blocks that give alien alloy and one working part 10 times in 16, so a full set takes a few wrecks.

### Phase 13b: phlogiston tech
- **3D like the frontier guns,** and the planned Phlogiston Generator was dropped: steam stays fuelled as it was (shards already burn in the boiler).
- **Phlogiston Cells:** 64 charges kept as durability; guns draw from the most worn cell first so they empty one at a time; an empty cell plus a shard recharges it.
- **The guns:** straight hitscan beams, no loading, no misfires. Ray Pistol 10 a shot; Phlogiston Rifle 30, which goes through three creatures (numbers from phase 33; see there).
- **The beam you see** is a short-lived entity drawn with vanilla's beacon-beam code from each gun's muzzle (set per gun from photos). From behind the shooter (F5) it runs away from the camera, so that view can't show it.
- **Sounds are synthesized** (`tools/music/Laser.java`): falling-pitch sweeps on detuned soft squares, checked by spectrogram. Borrowed vanilla sounds didn't read as lasers. Synthesized is the rule for sci-fi sounds from here on.
- **The gravity drive** is mended from the damaged one with phlogiston and starsteel (13c's heart).

### Phase 13c: the Prototype Saucer
- **Crafted, not built on a cradle** (the cradle was fiddly in playtest): 8 alien alloy around the mended gravity drive. Set it down like the airship; sneak-use folds it back up with fittings and charge kept as components. A new one comes primed with a cell's charge and the tractor beam and heat laser fitted; only the navigation core is fitted by hand.
- **Flight:** it faces where the pilot looks; W/S, A/D slide, jump climbs, sprint descends, no keys hovers. About three times the airship's speed. Run dry, it draws from the pilot's cells or shards, and the gauge says what to carry. Vertical speed brakes harder than it accelerates so it stops where you let go. Nothing harms it but `/kill`.

It overheats; it scorches the ground, never inside a town.
- **Tractor beam** (B): lifts creatures, items and players (unless the gamerule `hollowfrontier:saucer_beams_players` is off); a carried player struggles free by holding jump.
- **Camera:** third person rides 2.5 blocks above the pilot's line of sight (the mod's access transformer opens `Camera.move`, since NeoForge only exposes distance), easing out while beaming. A laser sight with a heat bar shows in third person too. The crew's first-person view skips the dome.
- **The model** is code-built: each layer a true 24-gon of bars whose ends sit on the circle (squares turned 15° apart made a star). The saucer draws translucent after the players so the pilot shows through the glass.
- **The crew can use what they hold aboard** (their crosshair is inside its hit box, so uses are passed through).

### Phase 13d: the Mothership

### Phase 22: gun enchantments
- **Effects in code** (`GunEnchantments.apply`), not effect components: vanilla's damage and spread effects only reach arrows and tridents, and the guns are hitscan. Mobs never hold enchanted guns.

- **Held right-click:** vanilla repeats a held use every 4 ticks, which bobbed the gun and fired each chamber as it loaded; `GunTrigger` cancels held repeats while loading.
- **Muzzle smoke** is sent per player: the shooter's own cloud starts at their barrel and is thinner, so it doesn't hide the target.

### Between phases 7 and 8: the frontier filled out (2026-10-27 to 10-28)

Two stars and the law shoots on sight and townsfolk won't trade; three brings posses. Cleared by a fine at the Bounty Board or by dying. Creative players are never wanted. During a raid, stray shots that hurt townsfolk or lawmen add no heat (kills still do).

Town cats don't flee players, lounge on pianos, bars and hay, gather at the fire pit at dusk, and keep snakes off. Morning gifts come through a global loot modifier, replacing rather than adding, so it's one small item.

- **Town raids:** a gang rides on a town at night (2.5% a check with a player inside, a day's grace and 3 days' cooldown, one raid in the world at a time, never with a 3-star player or posse there). The leader is an Outlaw Boss with a bounty; a safecracker works the vault, a dynamiter lobs dynamite that never breaks blocks, and the bagman carries 75% of the loot: bring him down and it all goes back. ### Phase 34 crash fixes (2026-11-05)
- **The cause:** `Mob` runs the full `GoalSelector.tick` (which stops goals whose `canContinueToUse` fails) only every other tick. Between times it calls `tickRunningGoals(false)`, which ticks every running goal with `requiresUpdateEveryTick` without asking. So a goal that clears its own field in `tick()` on a full tick is ticked once more with that field null. Which ticks are full depends on the entity's id and age, so it hit only some of the time, and a ticking-entity crash takes the whole world down.
- **Rule for every-tick goals:** `tick()` must cope with whatever it cleared on the tick before. Clearing a field only in `stop()` is always safe, since a stopped goal isn't ticked.
- **Audit:** all 11 files with every-tick goals were checked: a scan of each `tick()`, and the goals that keep a field read by hand. Only `Megatherium.BrowseGoal` (finished eating, or gave up on the path) and `FernSkitter.SnatchFoodGoal` (snatched) had it. Raid hiding clears a field in `tick()` too but already checks it first; the rest clear theirs in `stop()` or read a fresh `getTarget()` with a null check.
- **The tests drive the goal by hand** (`browse_survives_the_tick_after`, `snatch_survives_the_tick_after`), adding the extra tick, instead of waiting on the entity's parity. Both failed with the crash's own message before the fix. `megatherium_browses` and `skitter_snatches_food` couldn't catch it: they pass the moment the leaves or food are gone. `SnatchFoodGoal` went public for this, like `BrowseGoal`.
- **Shipped in 1.0.0:** both bugs date from the first commit. Fixed in 1.1.0.

### Safecrackers find the way in (2026-11-06)
- **The cause:** `PathFinder` drops any node whose walked distance reaches the mob's `FOLLOW_RANGE`, 40 for outlaws, and stops after 16 nodes per block of that. In a town on seed 4740615117784035791 the walk from the back of the bank at -3213, -2873 to its lobby is about 43 blocks, with a wall 3 blocks from the goal. - **The fix:** `Safecrack` calls `setRequiredPathLength(128)` while the goal runs, which raises both limits for him alone (2,048 nodes), and puts it back in `stop`. `FOLLOW_RANGE` stays at 40, so he doesn't see targets further off. ### Towns replace their dead (2026-11-06)
- **Asked for after a playtest:** towns should slowly replace the townsfolk and lawmen they lose. Nothing did before; a town only lost people.
- **Vacancies, not a census:** a resident's death puts their type, job (Folk or Rank) and post on their town's list in `TownVacancies`, its own saved data so raid records stay as they were. Each arrival takes one place off, so a town can't grow past what it started with, and no starting count had to be recorded. It works in towns generated before 1.1.4, but only for deaths from now on: nothing recorded the ones before.
- **Who counts:** anyone not marked a stranger. Folk that spawn from a structure or arrive as replacements are residents; everything else (spawn egg, command) is marked in `finalizeSpawn`, and freed men are marked when they settle or swear in, since they weren't there to begin with. A posse rider never counts. The mark is the inverse so that everyone already standing in an old world counts as a resident.
- **They come back in the same job at the same post:** a dead banker's place goes to a banker, and a barmaid's to a barmaid, because a town's trades are what a player misses. A lawman gets his rank, gun and post back. Trades start fresh, and a barmaid rolls a new name.
- **Where they appear:** at the post, usually indoors, rather than walking in from the street end. Folk plan only 32 blocks ahead (the safecracker's trouble again), so a walk across town would stall. Nobody appears within 8 blocks of a player, seen or not, or anywhere a player within 96 blocks has a clear line to. That line goes by what blocks the view, so glass doesn't hide them. If the post is in view but a spot within 3 blocks isn't, they use that spot and walk to the post. If there's no hidden spot at all, the place waits and the next on the list gets a try.
- **A lost building:** the ground over the post is only tried when nobody fits around the post at all. The first version tried it whenever the post was in view too, and a game test caught a new shopkeeper arriving on the roof because a player stood in the shop.
- **Timing:** `arrivals` and `arrivalTime` in `hollowfrontier-towns-server.toml`, default 24000 ticks (a Minecraft day, 20 minutes), counted from the death that started the list, then from each arrival. It's game time, so sleeping doesn't shorten it. Time away counts towards the next arrival only: come back after a week and one person is there, not everyone. That keeps "one at a time" true and simple; raise or lower `arrivalTime` to taste.
- **Never during a raid:** the town's list waits until the gang is gone. An unloaded post waits for a player to come near.
- **Not covered:** deaths outside the Overworld and folk outside towns (the Hollow Earth's camps) leave no place. Outlaws, horses and town cats aren't replaced.
- **Real town:** on the 1.1.4 jar with the pack's 111 server-side mods, killing 3 townsfolk and a marshal in the town at -3296, -2816 took it from 20 to 17, then back one at a time, 400 ticks apart on a test setting, to 20 and the marshal. The new marshal had his rank, post and rifle. The counts then held for the minute more it was watched.

### Town chests under Lootr (2026-11-06)
- **Replaces 1.1.3's blacklist:** `lootr:blacklist` turned out to stop town chests opening at all. Lootr's `unpackLootTable` hook closes the menu and cancels the unpack for any chest with a table, whatever the structure, then the tag refuses the conversion. That hook also hit the raid's own unpack, so a marked vault could be robbed of nothing. Towns are off the tag now, and ordinary town chests convert to per-player Lootr chests.
- **Vault chests stay plain:** `VaultChests` rolls a marked chest's table and clears it. Lootr can't help with a blacklist of its own here (its config rejects ids with a `/`), and conversion would drop `town_vault`. It doesn't touch any Lootr code, so there's no dependency, and it does the same with or without Lootr, so the path gets tested without it.
- **Timing:** queued on `ChunkEvent.Load`, done at the next `ServerTickEvent.Pre` at top priority, because filling a chest updates comparators, which shouldn't reach for chunks mid-load. Lootr queues a chest as it loads, only takes up new entries at the end of its `ServerTickEvent.Post` pass and re-reads the table before converting, skipping a chest with none. So a marked chest is always filled first. `unpackLootTable` isn't used, since Lootr cancels it.
- **Vault loot rolls earlier:** on load, not first opening. Nobody can tell, as the table and seed are the same, and a town's vault chests are only ever seen after their chunk loads.
- **Vault chests caught at any join (2026-11-07):** a playtest found a strongbox converted by Lootr despite all this: town at -353, -1570 on seed 4740615117784035791, joined 18 s after startup, raid said "no vault in town". The old jar did it again on a fresh world joined 14 s after startup, and kept every chest when joined over 2 minutes after (20 of 20 across nine towns). Two gaps in the code fit, though the run doesn't show which one bit: `stock` looked up the chunk by position next tick, which can come back empty for a chunk still on its way in, and read `getBlockEntities`, which leaves out pending block entities. It now holds the `LevelChunk` from the load event and walks `getBlockEntitiesPos` with `EntityCreationType.IMMEDIATE`. The fixed jar kept the strongbox on the same seed joined 11 s after startup. `vault_chests_stock_while_pending` fails on the old lookup and passes now; it covers pending chests, not the position lookup. No-player server runs never reproduced it, so a clean one proves nothing here.
- **Not covered:** a town put down by `/place` in chunks already loaded has no chunk load, so under Lootr its vault chests convert and it has no vault. Vault chests Lootr converted before 1.1.3 can't be recovered either.
- **Real run:** the pack's 111 server-side mods with Lootr and an empty `loot_table_modid_blacklist`. An older town went from 5 marked chests and 27 others with tables to 5 plain stocked chests (29 to 38 items each, none with a table), with no plain chest left holding a table. Around a newly generated town there were 40 Lootr chests, with its 2 vault chests plain and stocked. An unassisted gang of 6 cracked the older town's bank, taking its chests from 29 and 38 items to 2 and 5. That run used a throwaway jar with `ABANDON_TICKS` raised, like the safecracker's. No player opened a chest, so a Lootr chest's per-player loot and a vault chest opening by hand are for a playtest.

### New worlds start in town (2026-11-06)
- **Replaces the starting map:** a map on first join froze the server for each player: about 2 seconds in the pack, up to 12 here. Spawning at the town does the search once, while the world is created, and saves the first walk. The user chose this over the map. No `first_map` advancement or loot table shipped. The `hollowfrontier:towns` structure tag stays.
- **`TownSpawn`** handles `LevelEvent.CreateSpawnPosition`, which a world fires once, so existing worlds keep their spawn. It searches from the game's own origin, so the town is the one nearest where you'd have spawned.
- **The landing:** the town square is the start piece, and its middle holds a well or bandstand. `landing` spirals out from there to the nearest spot with a clear 3 x 3 yard: solid ground underfoot, no water, and nothing with a collision shape up to the top of the square. All 18 squares (3 styles, 6 layouts) have one in the game tests. The fallback if one ever didn't is the square's middle, which the game then lifts clear.
- **`respawn_radius` goes to 0 in these worlds.** At 10, the game drops each arrival on a random spot round the spawn, roofs included. It also overrides a value set while creating the world. It's only set when a town is chosen, and an operator can change it back.
- **Bedless respawn:** you come back to the same spot in the square. A respawn with no bed uses the world spawn.
- **Config:** `spawnAtTown` in `hollowfrontier-towns-server.toml`. SYNCED configs load before the world on both dedicated and integrated servers, and the `config` folder copy is the one that exists before a world does, so that's where it's set. A world's own `syncedconfig` copy can't work: the choice is already made by then.
- **No town in reach:** 16 steps of the 40-chunk grid, about 10,000 blocks. Beyond that the game picks the spawn as usual, which costs nothing but the search. The furthest nearest town in 288 searches was 7,634 blocks, and 3,983 in the pack's 24.
- **Search times, HF alone (no Terralith), three servers running at once:** 20 normal worlds and 6 large-biome worlds all started on a town, in 2.2-5.9s and 2.7-7.0s. Amplified: 5 of 6 worlds had no town in reach and fell back after 7.0-8.1s; the sixth found one in 4.7s. Those times include generating the square's chunks. The normal runs were at 32 steps, but every town found is inside 16.
- **Watchdog:** none. A dedicated server starts its watchdog after `loadLevel`, and the search runs inside it. Singleplayer has no watchdog. A slow search only means a longer wait for the world.
- **The survey now stops at its first bad reading.** Amplified failed every search, and each took 54-282s at the old map radius of 50 steps, which is why it could not stay as it was. `levelGround` read all 58 heights before judging them. It now stops at the first water or the first reading past `maxSlope`, which gives the same answer sooner. 36 `/locate` searches on seed 1897 gave the same distances as before. It speeds up `/locate` too.
- **Bonus chest:** cancelling the event skips the game's own, so `TownSpawn` places it. Untested: a dedicated server can't ask for one.
- **Spawn protection:** at the default radius of 16, on a dedicated server with at least one operator, non-operators can't use blocks near the spawn, and that's now the middle of a town. The mod can't change a `server.properties` value, so the docs say to set `spawn-protection=0`. The pack's server already does.
- **Real client:** a real signed-in dev client joined a fresh dedicated-server world (seed 10, HF plus the dev Curios, Jade and JEI). It landed at 415.5, 66, 722.5 on the ground at full health, the spot `TownSpawn` chose. Killed with no bed, it came back to the same spot. This spot held a thin layer of snow, which has no collision. Two other worlds' spots also weren't plain air; those weren't looked at, but the landing check rules out anything with a collision shape.
- **Off switch:** with `spawnAtTown = false` in the `config` folder, a fresh world took the game's usual spawn.
- **Not tested:** creating a world in singleplayer (its loading screen), Terralith on this jar (the pack's own 8-seed probe found towns in 1.3-3.1s), several players arriving together, and looking at the town from the landing.
- **`logoFile`:** the dev client stopped at a warning screen about the deprecated key, before quick play could join. `bannerFile` replaces it.
- **Acts out of order:** a saucer can come before the Hollow Earth, which put a listener past `Act.GATEWAY` without their having gone down, so Hollow Earth lines reached them. Lines from `Act.GATEWAY` now also need `Context.beenDown`. The act ladder stays as it is, since the later acts' lines only assume what the player has seen.

### 43a the sea itself (2026-11-09)
- **Where:** continentalness under -0.30 (`HollowBiomes.SEA_CONTINENTS`), whatever the weather. Over five seeds that's 18% of the Hollow, and every seed has sea within 2 km of the origin.
- **The land already lay low there.** The land's height is 72 + 30 x continents, so under -0.30 it was already at or under sea level 63: before 43a much of it was shallow, muddy lake carrying a land biome. Of 934 sea samples over five seeds, 618 (two in three) were already under sea level; the rest were low hills and are now beach or water.
- **The shape:** a shore 0.04 of continentalness wide brings whatever stands at the edge down to a beach 1.5 over the water; a shelf 0.22 wide lowers the bed to a rolling floor 15 to 35 under the surface (by the ridges noise). The bed is never raised: where the old land lay lower still it keeps its depth (the deepest test sample was 36 under).
- **By construction, not by baseline.** The spec asked for land sample points taken before the change. Instead the old height is kept as its own density function (`hollow_earth/land_height`) and the old climate table as `parametersBeforeTheSea`, and `still_sea_takes_only_the_low_ground` holds today's height and biome equal to them at every sample at or over the threshold (about 4,000 over five seeds). That can't go stale and needs no stored numbers.
- **Tags:** `is_hollow_earth` gains the sea. A new `is_hollow_land` (the four land biomes) now places the three sites that used `is_hollow_earth` (Symmes camp, Hollow crash site, Sky Shrine); their land biomes are the same, so they stand where they stood. The sea is in no vanilla water tag, and a test fails if any structure may start in it (43d's Drowned Quarter should change that test).
- **Kelp and seagrass are our own features.** Vanilla's look the bed up in the ocean-floor heightmap, which under the crust is the roof of the world. `seabed_scan` starts just under the surface and goes down through water. Kelp keeps to water 4 to 26 deep, seagrass to 14, so the deep is open water.
- **The ground:** sand on the beach and shallows, gravel and clay patches on the deep bed, sandstone under it, stone where the shore is steep, grass on anything 6 or more over the water.
- **Left for later parts:** the biome has vanilla cod, salmon, tropical fish and squid until 43b. It isn't in the "walk every biome" advancement (the sea is a side road; 43d's Codex chapter covers it).
- **Checked in the client** (`-PphotoScene=sea`, `hf_43a_*`): the sea from above, from the surface and underwater (kelp forests on the shelf), and a shore (a pale sand beach under the jungle). The photo world held 10 old chunks saved as land where the generator now says deep sea; from above the coast there reads as a natural one, with no wall or step showing. Those chunks were already lake, though: a place where old dry land meets new sea (the other third) wasn't found in the photo world, so the worst case of the seam is still unseen. Look for one on a copy of a 1.1.x world before release.
- **Not shot:** a sea stack. No spire reached the water within a kilometre of the sea nearest the staging spot (the lowest ended at y 183). **Not checked:** whether fish and squid spawn in numbers under the ceiling, and the ambient sound by ear.
- **The photo world's log** fills with "unknown registry key hyperborean_highlands" errors when its oldest Hollow chunks load. They date from a biome renamed early in development and have nothing to do with the sea.

### 43b sea life (2026-11-09)
- **Their own spawner, not biome spawn entries** (`SeaLife`, the spec said "by biome tag"; the tag `has_sea_life` is still what decides where). Vanilla picks spawn heights under a heightmap that here is the crust, so 30 blocks of water under 250 of air are found too rarely to stock a sea, and each kind wants its own depth. Every 100 ticks, per player in tagged water, one spot 24 to 56 blocks off is tried for one kind: sea cows in water 4 to 14 deep, Lampjellies 4 and over, a Plesiosaur 10 and over, a Basilosaurus 18 and over, each up to its own number within 96 blocks.
- **Who stays:** the Great Sea Cow is an `Animal` (it breeds), so it never despawns; the other three drift off when nobody's near, as fish do, unless named.
- **Great Sea Cow:** 30 health, never fights. It eats the top off a kelp stalk every one to two minutes and leaves the stalk to grow back; it won't eat a plant with no stalk under it. Kelp leads and breeds it. 2 to 3 Blubber.
- **Basilosaurus:** 80 health, 9 a bite. Prey is anything afloat (or riding something afloat) over water 6 or more deep; the shallows are safe, and it gives up three seconds after its prey reaches them. It circles 3 to 5.5 seconds at ten blocks, then strikes. A bitten rider's boat takes 6 as well. Hurt, it comes for whoever did it wherever they stand. Ramming the submersible is 43c's.
- **Plesiosaur:** 50 health, keeps ten blocks off anyone not holding a fish, bites back if hurt. A fish sends it to the bed and back (each leg times out, so it can't be lost down there) with one or two rolls of `gameplay/plesiosaur_dive`: kelp, seagrass, clay, bone, nautilus shell, prismarine, Lamp Gel, and at about 1 roll in 9 one of the Hollow's sherds or relics. Then a two-minute rest. **It doesn't yet look toward the Drowned Quarter:** there isn't one until 43d (`SeaLife.quarterBearing` is the seam), so it looks at whoever fed it.
- **Lampjelly:** 4 health, a sting of 1 and three seconds of poison, at most every two seconds. 0 to 2 Lamp Gel.
- **Tallow** burns as long as coal (the vanilla coal burn time on a `cooking_fuel` component, so the Boiler takes it too) and makes two candles with a string. Its real job, the submersible's gaskets, is 43c's. **Jelly Lamp:** light 15, four gel round a glass block.
- **The Harpoon** is a trident with Loyalty II built in and no drawing back: use it and it's thrown. 7 damage (the Toothed Harpoon 10; a trident is 8), a trident's water inertia, and it comes back after a hit, a miss, or 2.5 seconds of flight. 120 uses, 250 with teeth. Iron, a stick and a lead; two Basilosaur teeth upgrade it. It's drawn in flight as its item, as the lasso is, and the line itself isn't drawn.
- **Phlogiston beams underwater:** left as they are. Black powder already always misfires underwater; the beams were never stopped by water, and a late-game gun that works there is a fair reward. No code changed.
- **Advancements are a branch of their own** under a new "reach the Still Sea" (the spec said to add the creatures to the megafauna advancements). Big Game and World Within are challenges some players have already earned or half-earned, and the sea is a side road; nobody should have to kill a sea cow for a challenge. Six new ones: the sea, blubber, Lamp Gel, a harpoon, a Plesiosaur's fetch, and a Basilosaurus.
- **Tests run the hunt and the sting on a sea cow, not a fake player.** A fake player never ticks, so it never leaves its 60 ticks of spawn invulnerability and can't be hurt by a mob. `isPrey` is still checked against real fake players (swimmer, wader, creative).
- **Caught by the tests:** `TemptGoal` needs the `tempt_range` attribute, which only `Animal` attributes carry; the Plesiosaur crashed the world on its first tick until it had one.
- **Every-tick goals** (phase 34's rule): only `Basilosaurus.HuntGoal`. It reads its target fresh each tick and clears its own state only in `start` and `stop`; its test ticks it after the target is gone and after it's stopped. The sea cow's `GrazeGoal` isn't every-tick and clears its field only in `stop`; the Plesiosaur's dive runs in the entity's own step, not a goal.
- **Checked in the client** (`-PphotoScene=sealife`, `hf_43b_*`): all four render, swim poses and the jellies' glow included. **Not checked in the client:** the creatures moving under their own AI, natural stocking in a real sea, the calf's half size, the bite and dive animations, the harpoon in flight, and every sound by ear. Underwater, everything reads dark.
- **After the 2026-11-09 playtest: each kind keeps to its own depth.** The user found all four spending too much time at the surface. Two causes: `SeaLife` put them in the upper half of the water, and vanilla's random swimming picks a spot up to seven blocks up or down, which the surface keeps turning back, so idlers collect under it. `SwimAtDepthGoal` now takes vanilla's spot for where and sets the depth itself, and `SeaLife` places by the same band: sea cows within 5 of the bed and 2 under the surface; Lampjellies anywhere 3 or more under; the Plesiosaur 4 or more under, coming up for a look 15% of the time; the Basilosaurus 8 or more under and within 10 of the bed. A sea cow still comes up to graze, since kelp tips reach nearly to the surface.

### 43c the Steam Submersible (2026-11-09)
- **Built like the airship** (`SteamSubmersible`, a `VehicleEntity` run on the server from the pilot's keys, owner-locked, folding into an item that keeps its steam), with its own class rather than a shared base: the two differ in everything but the plumbing.
- **Steam:** 16,000 mB. The screw takes 2 a tick and the ballast pumps 1 while rising or diving; holding still is free. That's about 6.5 minutes of driving, or roughly 2,500 blocks at 0.32 a tick. Astern is half speed.
- **Charging:** canisters by hand, or by itself from any steam holder within a block of the hull, 500 mB every 5 ticks while it's stopped. The spec said "at the waterline"; a block's reach in every direction covers a tank on a jetty, a pipe run down into the water and a boiler on the bank alike.
- **Launching:** used on water, as a boat is, and it always starts awash however deep the water looked at. It refuses dry land, where it could never move again. Out of the water (a lake drained under it) it drops, sits, and neither drives nor spends steam.
- **Dry:** it rises at a third of pumping speed until it's awash, then stays there. It can't drive or dive until it's charged.
- **The dome is glass by cutout** (art pass, at the user's asking, after a playtest found the screw clipped into the fin and the hull reading as a plain box). The first model had an open cage of four posts, for fear a solid dome would block the view from inside. The dome is now a box whose faces are clear but for a post at each corner and a rail round the top (a second playtest found mullions and glints filling the view from the pilot's seat, so they went, and the seats moved back from the glass), which the cutout render type draws as open, so the crew sees out through it; `runPhoto` shows the far side through the near one. The hull gained a deck, keel, stepped bow and stern, ballast tanks, planes and a snorkel; brighter brass; and a glow mask for the lamp and ports. The hit box is 1.9 high now, to take in the dome.
- **Crew:** air is topped up every tick, and night vision (hidden, 15 seconds, renewed each second) is the lamp. Getting out takes the lamp away at once, unless the rider has a potion of their own. No light is cast into the world: a moving light source would mean placing and clearing light blocks as it goes.
- **The hull:** players who may handle it break it up as they break a boat. Anything else alive wears a hull of 40 instead, because vanilla's vehicle damage would break it at the first bump and put its crew in deep water beside whatever bumped it. A Basilosaurus's ram is 8, so five in a row; the hull mends 1 every 5 seconds. Folding and relaunching mends it outright, which is fine: that takes its owner, on the surface.
- **The ram** finishes 43b's Basilosaurus: a rider in a submersible is prey over deep water like anyone afloat, but the bite goes to the hull and the rider isn't hurt.
- **Recipe:** two brass plates and glass over two Tallow and a Lamp Gel over two copper blocks and a brass gear. It needs the sea's own drops, so the first trip out is by boat or airship.
- **Advancement:** "No Fire Below" in Steam Age, after the airship. **Jade:** steam and hull, through the vehicle provider the airship uses. The camera pulls back as it does for the airship.
- **The gauge** (steam, depth, hull) shows on the pilot's action bar, as the airship's does.
- **Checked in the client** (`-PphotoScene=submersible`, `hf_43c_*`): it renders awash and submerged, sitting where it's put. **Not checked in the client:** driving it by hand, the view from inside, the lamp, the Jade tooltip, the screw turning, and a real ram. After the art pass: the reworked model awash and submerged, the dome see-through, the ports and lamp lit. The view from the pilot's seat is still unchecked.

### Phase 45 the Hollow, heard (2026-11-10)
- **The user's calls (2026-11-10):** the score is synthesized here, not composed or recorded by the user; it replaces vanilla's music in the Hollow outright, with a client switch back; up to 10 MB more in the jar; the release is 1.4.0. All four were put to them as defaults and accepted with "start 45a".
- **45a, one idea five ways.** Every piece is long cross-fading chords in the reveal swell's tone under a sparse lead, and each states the swell's rising figure (E, F sharp, G sharp, B) once. What changes is the mode, the register and the lead: E major and a soft reed (jungle), E lydian and glass bells with seeded "wind chimes" (steppes), E minor with a phrygian chord and a low reed in a small hall (badlands), open fifths in E mixolydian and one wordless voice (highlands), C sharp minor with chords that breathe at about 0.085 Hz and an arrival on the swell's own E chord (sea). No pulse and no percussion, so nothing loops audibly and nothing tires.
- **Stereo, where the spec said mono.** Background music isn't played from a position, so the reason the piano and the discs are mono doesn't apply, and pads spread left, middle and right with a hall a few samples different in each ear are much of what makes them sound like a place. The files stay inside the budget (sizes in ASSETS.md).
- **Quieter than the piano:** normalised to -21 LUFS (the piano's tunes are -18), since this plays under everything else for hours. If it's too quiet or too loud by ear, change the loudness pass, not the synth.
- **The bass is kept light.** The first render had the lowest chord notes as loud as the rest, some under 45 Hz. They're now a third quieter, and anything under 65 Hz quieter again; the leads came up by half. This was judged from spectrograms and the gains, not by ear.
- **The biomes name the pieces; the client only swaps them out.** `BACKGROUND_MUSIC` in each biome is ours, so the game's own music manager plays them with vanilla's gaps and its "now playing" toast names them (lang `hollowfrontier.music.hollow.<biome>`, the key the toast builds from the file's path). `client/HollowScore` does one thing: with `hollowScore` off it swaps a piece for the vanilla music that biome had, at high priority so `TownSoundscape` still gets to hold the music near a piano.
- **The mod's first client config** (`ClientConfig`, `hollowfrontier-client.toml`), registered from `HollowFrontierClient` so a dedicated server never loads it.
- **`/hfaudition`, not `/hollowfrontier audition`.** It's a client command, and a client command under the server's root would have to rely on the client dispatcher passing every other `/hollowfrontier` line through to the server. A root of its own can't get in the way. It lives in the `dev` source set, so it's in every dev run and never in the jar.
- **Tests:** every registered sound event has a `sounds.json` entry and every recording of ours an entry names is in the jar (this covers every event, not only the new ones); each Hollow biome's JSON names its piece and no vanilla music; the pieces are streamed. The switch isn't tested: it needs a client.
- **Not checked by ear.** Rendered, measured (loudness, peak) and looked at as spectrograms only. The user's listening in `runClient` is what 45a's *Done when* waits on.
- **45a heard (2026-11-10):** the user listened and said it sounds good, so 45a is done.
- **45b, the beds are noise and a few sines** (`tools/music/HollowBeds.java`): seven loops, 32 or 36 seconds (the submersible's thrum is 2). A loop is seamless by construction: every slow change runs a whole number of times in it, every tone fits a whole number of cycles, events near the end wrap to the start, and the noise is rendered three seconds long and cross-faded into its own beginning. The filters are state-variable, which stay steady while their frequency is swept.
- **Constant gain, no loudness pass.** `loudnorm` can change its gain as it goes, which would put a step at the loop point, so each bed is measured and turned down by one fixed amount: the land beds to -30 LUFS, the sea's to -34 (it's meant to be nearly nothing), the deep bed to -26 and the thrum to -24 (the client sets those two's volume as it plays them). They can be turned down further in `sounds.json` without re-rendering.
- **The beds play at 0.7** (the user's listening, 2026-11-10: "about 30% quieter"). Set as `volume` in `sounds.json` on all six loops, the deep bed included; the recordings are unchanged. The far calls, the rumble and the submersible's sounds were left as they were.
- **Then everything 20% quieter** (the user, 2026-11-10: "make all the sounds 20% quieter"), taken as everything phase 45 added and nothing older: the score plays at 0.8, the beds at 0.56 (0.7 x 0.8), the thrum at 0.8, the creak's and the rumble's parts at 0.8 of what they were, and a far call arrives at 0.3 of full, not 0.375. All in `sounds.json` or one number in `HollowSoundscape`; no recording changed. 45c's themes and stings are built to the same 0.8.
- **The biome beds use vanilla's own loop slot** (`AmbientSounds.loop`, which `HollowBiomes.ambient` left empty), so the game starts, cross-fades and stops them at biome borders. No code of ours plays them.
- **Far calls are the creatures' own sound events**, placed 40 to 80 blocks off and played with enough volume to carry there (a sound carries 16 blocks a point of volume), a little low in pitch. So they come from a direction, and their subtitles are the creatures' own. Which creature is heard where follows the megafauna's biome tags and the sea's, and a test holds them to it. A mean of one call in 90 seconds and one rumble in six minutes (`HollowAmbience`).

A Gray Probe, Sentinel, Drone, Warden or Saucer within 64 blocks hushes the calls and the rumble. A Gray site that has been cleared out sounds like anywhere else again, which suits it.

### Phase 46 the frontier, felt (2026-11-10)
- **The user's calls (2026-11-10):** the kick is for the eyes only and never moves the aim; camera movement is on by default behind two sliders that go to zero; dust is for every horse, vanilla's included; and it ships in 1.4.0 with phase 45. The one thing made to sync is the horseshoe tier, so a client knows a horse is shod.
- **The kick is found, not sent.** The client watches the gun in each hand for a "last fired" that has just changed to now, as the recoil animation does. A gun drawn with an old shot on it doesn't kick.
- **Server side, where everyone must see it:** chips, sparks, splashes, the thud, the near miss and the haze come from `GunFeel`, called from `GunMechanics.fire`. Only two pellets of a shot make a sound where they land (a Blunderbuss would otherwise play eight). A near miss is told to each player once a shot, never to the shooter or anyone hit, and not within four blocks of the muzzle.
- **"Hard" is whatever a pickaxe mines, plus glass.** That covers stone, ore, brick and metal without a list. Everything else is soft.
- **The haze is renewed, not one long particle.** No vanilla smoke both stays put and lasts several seconds, so the server keeps a short list of hazes and feeds each for three seconds after the last shot that made it: wisps of white smoke every five ticks, and every ten a campfire's billow, the one vanilla smoke that hangs, which then fades by itself over the next several seconds. (White smoke alone, the first try, could hardly be seen in the client.) Sixteen hazes a level at most. Outlaws' shots count as much as players'.
- **Dynamite got a sound of its own** (a low thump under vanilla's bang, carried 64 blocks), which is also how the client knows a blast was dynamite.
- **The lasso got its wind-up after all** (the user, 2026-11-11: "I didn't see the lasso whirling"). The first build only played a sound as it was thrown. Now use is held: the arm goes up (the trident's pose), a loop of rope whirls overhead on a line from the hand with a swish every turn, and letting go throws. The throw's power is fixed, so a quick click throws exactly as before and nothing about catching changed. In the air the lasso is a whirling loop on a line back to the thrower's hand (`LassoRenderer`), where it was the item's sprite (`ThrownItemRenderer`).
- **Signed off (2026-11-11):** the user looked at the lasso and the horseshoes and said they look good. That covers those two; the rest of phase 46 is still as PLAN.md's open item has it.
- **A circle spinning in its own plane looks still,** so the loop is tilted and the tilt goes round, and the knot where the line joins travels the rim (`RopeDraw`). It's drawn with the Harpoon's rope texture, so there's no new art for it.
- **The wind-up loop is a layer on the player's renderer,** so other players see it and the thrower does in third person. In first person a player's layers aren't drawn: there you see the raised lasso and hear it, then the loop as it flies out.
- **Horseshoes are drawn** (the user, same day): a layer on every vanilla horse renderer draws the horse's own model again in a sheet that is clear except for a two-pixel band round the foot of the leg and a shoe on its underside, one sheet a tier (`textures/entity/horseshoes_*.png`, from `TextureArt.horseshoes`). ### Phase 47 a stake in town (2026-11-11)
